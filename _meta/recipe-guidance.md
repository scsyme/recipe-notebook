# Maintaining the recipe notebook

## Kitchen pairings

Would knowing about another recipe change what the cook does next? If so, add a **Kitchen pairing** section to each recipe. Write each note from the perspective of someone who opened that recipe first. Put it before the decision it affects, especially when the cook might discard something useful.

Give one concrete action, a quantity where useful, and a relative link to the companion recipe. Check that both links resolve and that the quantities make sense in each direction.

For example, the [chickpea cookies](../recipes/peanut-butter-and-chocolate-chip-chickpea-cookies.md#kitchen-pairing) tell the cook to catch about 120 ml of liquid when draining the chickpeas. The [aquafaba mousse](../recipes/aquafaba-chocolate-mousse.md#kitchen-pairing) tells the cook to weigh the chickpeas because a full batch of cookies needs 600 g drained. Each note helps with a different decision.

## Adding a recipe

- Keep one Markdown file per recipe in `recipes/`. Add a relative link to it in the alphabetical README index.
- Include the yield when known, the ingredients with quantities and a numbered method in cooking order. Use UK terminology and metric units. Preserve useful cues such as “until golden” and “until the centre still wobbles”.
- Write the instructions in your own words. Credit the creator and link the original source. If a description or reproduced caption supplied the details, identify it and link it where available.
- Preserve approximations, flag missing details that affect the cook and label any suggested additions. Give the oven setting as unspecified when the source only gives a temperature.

## After cooking

Use **Unrecorded** in the index until a cook is confirmed. After a cook, update the index and add a dated entry under **My kitchen notes** in the recipe. Record what was tried, how it turned out and what to change next time. Keep the sourced method available so the two versions can be compared.
